# Transaction Ledger API: API Documentation

A REST API for accounts, credit/debit transactions, balances, transaction history and money
transfers.

- **Base URL:** `http://localhost:8000` when run as described in the [README](README.md)
- **Interactive docs (Swagger UI):** `http://localhost:8000/docs`
- **Design assumptions** (duplicates, pagination limits, money precision, transfers):
  see [README → Assumptions](README.md#assumptions)
- **OpenAPI spec:** `http://localhost:8000/openapi.json`

## Conventions

| Topic | Convention |
|---|---|
| Format | Request and response bodies are JSON. Send `Content-Type: application/json`. |
| IDs | UUIDs generated by the server, e.g. `b2fee5b0-2432-4a9b-948b-3c0311d9b309`. |
| Money | Returned as **decimal strings with 2 places** (`"150.00"`), so values stay exact. `amount` in requests can be a JSON number (`150`) or a string (`"150.00"`). At most 2 decimal places. |
| Timestamps | ISO 8601 in UTC, e.g. `2026-10-27T20:35:19.122374Z`. Always generated by the server. |
| Unknown fields | Request bodies **reject unknown fields** with `400 VALIDATION_ERROR`. For example, a client cannot send `balance` when creating an account. |
| Strings | `name`, `reference_id` and `description` are trimmed of surrounding whitespace. |
| Immutability | Transactions cannot be edited or deleted. There are no PUT, PATCH or DELETE endpoints. |

## Error format

Every error response has the same shape:

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient balance for this debit",
    "details": { "...": "extra context, when available" }
  }
}
```

For validation errors, `details` is a list with one entry per problem:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request data",
    "details": [
      { "field": "type",         "location": "body", "message": "Input should be 'credit' or 'debit'" },
      { "field": "amount",       "location": "body", "message": "Input should be greater than 0" },
      { "field": "reference_id", "location": "body", "message": "Field required" }
    ]
  }
}
```
`location` is one of `body`, `query` or `path`.

### Status and error codes

| HTTP status | `code` | Meaning |
|---|---|---|
| `400 Bad Request` | `VALIDATION_ERROR` | Invalid or missing body fields, malformed JSON, unknown fields, malformed UUID, invalid `type`/`page`/`limit`, transfer to the same account |
| `404 Not Found` | `ACCOUNT_NOT_FOUND` | The account does not exist |
| `404 Not Found` | `NOT_FOUND` | The URL does not exist |
| `405 Method Not Allowed` | `METHOD_NOT_ALLOWED` | The method is not supported, e.g. trying to edit or delete transactions |
| `409 Conflict` | `DUPLICATE_TRANSACTION` | The `reference_id` was already used on this account. Nothing was changed |
| `422 Unprocessable Content` | `INSUFFICIENT_BALANCE` | A debit or transfer exceeds the available balance. Nothing was changed |
| `500 Internal Server Error` | `INTERNAL_ERROR` | Unexpected server error. Internal details are logged, never returned |

## Data model

### Account
| Field | Type | Description |
|---|---|---|
| `id` | UUID | Unique account identifier (server-generated) |
| `name` | string | Account holder name (1–255 characters) |
| `balance` | decimal string | Current balance. Starts at `"0.00"` and never goes below 0 |
| `created_at` | timestamp | When the account was created (server-generated) |

### Transaction
| Field | Type | Description |
|---|---|---|
| `id` | UUID | Unique transaction identifier (server-generated) |
| `account_id` | UUID | The account this transaction belongs to |
| `type` | `"credit"` \| `"debit"` | Credit adds to the balance; debit subtracts from it |
| `amount` | decimal string | Amount, always > 0 |
| `description` | string \| null | Optional description (up to 500 characters) |
| `reference_id` | string | Client-supplied reference, **unique per account** (1–100 characters) |
| `created_at` | timestamp | When the transaction was created (server-generated) |

## Endpoints

### 1. Create account

`POST /accounts`

Creates a new account. The balance always starts at **0**, and `id` and `created_at` are
generated by the server.

**Request body**

| Field | Type | Required | Rules |
|---|---|---|---|
| `name` | string | ✅ | Not empty or blank, max 255 characters |

No other fields are accepted. Sending `balance`, `id` or `created_at` returns `400`.

**Example request**
```bash
curl -X POST http://localhost:8000/accounts \
  -H "Content-Type: application/json" \
  -d '{"name": "Alice"}'
```

**Response `201 Created`**
```json
{
  "id": "b2fee5b0-2432-4a9b-948b-3c0311d9b309",
  "name": "Alice",
  "balance": "0.00",
  "created_at": "2026-10-27T20:35:19.122374Z"
}
```

**Errors**

| Status | `code` | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | `name` is missing, empty or blank, the body is not valid JSON, or the body has extra fields such as `balance` |

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request data",
    "details": [{ "field": "balance", "location": "body", "message": "Extra inputs are not permitted" }]
  }
}
```

### 4. Add transaction

`POST /accounts/{account_id}/transactions`

Adds a credit or debit to an account and updates its balance in **one atomic operation**:
either both the transaction and the new balance are saved, or neither is.

**Rules**
- **Credit** increases the balance by `amount` (100 + 50 → 150).
- **Debit** decreases the balance by `amount` (100 − 30 → 70).
- A debit larger than the current balance is **rejected** (`422`), and the balance is unchanged.
- `reference_id` must be unique **per account**. Submitting the same `reference_id` again for
  the same account creates nothing, leaves the balance unchanged and returns `409` with the
  existing transaction. Other accounts can reuse the same `reference_id`.
- Concurrent requests on the same account are processed one at a time (row lock), so parallel
  debits can never overdraw the account.

**Path parameters**

| Name | Type | Description |
|---|---|---|
| `account_id` | UUID | The account to post to |

**Request body**

| Field | Type | Required | Rules |
|---|---|---|---|
| `type` | string | ✅ | `"credit"` or `"debit"` |
| `amount` | number or string | ✅ | > 0, at most 2 decimal places |
| `reference_id` | string | ✅ | Not empty or blank, max 100 characters, unique per account |
| `description` | string | ❌ | Max 500 characters |

**Example request**
```bash
curl -X POST http://localhost:8000/accounts/b2fee5b0-2432-4a9b-948b-3c0311d9b309/transactions \
  -H "Content-Type: application/json" \
  -d '{"type": "credit", "amount": 100, "description": "Salary", "reference_id": "inv-001"}'
```

**Response `201 Created`**: the new transaction and the account's balance after it.
```json
{
  "transaction": {
    "id": "8d9002b3-308f-4b42-87dc-60a4546ccbfc",
    "account_id": "b2fee5b0-2432-4a9b-948b-3c0311d9b309",
    "type": "credit",
    "amount": "100.00",
    "description": "Salary",
    "reference_id": "inv-001",
    "created_at": "2026-10-27T20:35:19.275784Z"
  },
  "balance": "100.00"
}
```

**Errors**

| Status | `code` | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Invalid `type`; `amount` missing, ≤ 0, not a number or with more than 2 decimals; `reference_id` missing or blank; unknown fields; invalid JSON; malformed `account_id` |
| 404 | `ACCOUNT_NOT_FOUND` | The account does not exist |
| 409 | `DUPLICATE_TRANSACTION` | `reference_id` already used on this account |
| 422 | `INSUFFICIENT_BALANCE` | Debit amount is greater than the current balance |

`409` duplicate transaction (`details.transaction` is the transaction that already exists):
```json
{
  "error": {
    "code": "DUPLICATE_TRANSACTION",
    "message": "Transaction with reference_id 'inv-001' already exists for this account",
    "details": {
      "transaction": {
        "id": "8d9002b3-308f-4b42-87dc-60a4546ccbfc",
        "account_id": "b2fee5b0-2432-4a9b-948b-3c0311d9b309",
        "type": "credit",
        "amount": "100.00",
        "description": "Salary",
        "reference_id": "inv-001",
        "created_at": "2026-10-27T20:35:19.275784Z"
      }
    }
  }
}
```

`422` insufficient balance:
```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient balance for this debit",
    "details": {
      "account_id": "b2fee5b0-2432-4a9b-948b-3c0311d9b309",
      "balance": "70.00",
      "requested_amount": "150.00"
    }
  }
}
```

### 5. Get transaction history

`GET /accounts/{account_id}/transactions`

Returns an account's transactions, **latest first** (sorted by `created_at` descending), with
optional filtering and pagination.

**Path parameters**

| Name | Type | Description |
|---|---|---|
| `account_id` | UUID | The account ID |

**Query parameters**

| Name | Type | Default | Rules |
|---|---|---|---|
| `type` | string | both types | `credit` or `debit`. Leave it out to get both |
| `page` | integer | `1` | ≥ 1 |
| `limit` | integer | `10` | 1–100 (page size) |

**Example request**
```bash
curl "http://localhost:8000/accounts/b2fee5b0-2432-4a9b-948b-3c0311d9b309/transactions?page=1&limit=2"
```

**Response `200 OK`**
```json
{
  "data": [
    {
      "id": "5c55b5b0-7664-48ff-b641-ff4d7a17e5f5",
      "account_id": "b2fee5b0-2432-4a9b-948b-3c0311d9b309",
      "type": "debit",
      "amount": "30.00",
      "description": "Groceries",
      "reference_id": "inv-002",
      "created_at": "2026-10-27T20:35:19.321202Z"
    },
    {
      "id": "8d9002b3-308f-4b42-87dc-60a4546ccbfc",
      "account_id": "b2fee5b0-2432-4a9b-948b-3c0311d9b309",
      "type": "credit",
      "amount": "100.00",
      "description": "Salary",
      "reference_id": "inv-001",
      "created_at": "2026-10-27T20:35:19.275784Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 2,
    "total_records": 2,
    "total_pages": 1
  }
}
```

**Pagination fields**

| Field | Description |
|---|---|
| `page` | The current page number |
| `limit` | Page size (maximum number of items on this page) |
| `total_records` | Total transactions matching the filter, across all pages |
| `total_pages` | `ceil(total_records / limit)`. `0` when there are no transactions |

A `page` beyond `total_pages` returns `200` with an empty `data` list.

**Errors**

| Status | `code` | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | `type` is not `credit`/`debit`; `page` < 1 or not an integer; `limit` outside 1–100 or not an integer; malformed `account_id` |
| 404 | `ACCOUNT_NOT_FOUND` | The account does not exist |

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request data",
    "details": [{ "field": "page", "location": "query", "message": "Input should be greater than or equal to 1" }]
  }
}
```

### 6. Transfer money (bonus)

`POST /transfers`

Moves money from one account to another. This records a **debit** on the source account and a
**credit** on the destination account, and both are saved **atomically**. If any part fails,
the whole transfer is rolled back, so a partial transfer is never possible.

**Rules**
- Both accounts must exist and must be different accounts.
- The source account must have a sufficient balance.
- Both transactions use the transfer's `reference_id`. Retrying the same transfer returns
  `409` instead of moving the money twice.
- If no `description` is given, the server sets one: "Transfer to {id}" or "Transfer from {id}".

**Request body**

| Field | Type | Required | Rules |
|---|---|---|---|
| `from_account_id` | UUID | ✅ | Source account; must exist |
| `to_account_id` | UUID | ✅ | Destination account; must exist and differ from the source |
| `amount` | number or string | ✅ | > 0, at most 2 decimal places |
| `reference_id` | string | ✅ | Not empty or blank, max 100 characters; must be unused on both accounts |
| `description` | string | ❌ | Max 500 characters |

**Example request**
```bash
curl -X POST http://localhost:8000/transfers \
  -H "Content-Type: application/json" \
  -d '{
        "from_account_id": "b2fee5b0-2432-4a9b-948b-3c0311d9b309",
        "to_account_id": "69192f20-26e1-465c-829b-0069e4aa6649",
        "amount": 30,
        "description": "Rent share",
        "reference_id": "tr-001"
      }'
```

**Response `201 Created`**
```json
{
  "reference_id": "tr-001",
  "amount": "30.00",
  "debit_transaction": {
    "id": "350a756a-c15b-4998-8eff-99bee6f45e4e",
    "account_id": "b2fee5b0-2432-4a9b-948b-3c0311d9b309",
    "type": "debit",
    "amount": "30.00",
    "description": "Rent share",
    "reference_id": "tr-001",
    "created_at": "2026-10-27T20:35:19.524720Z"
  },
  "credit_transaction": {
    "id": "9ff83a72-5c8c-4df7-82fe-d9fe427eef0d",
    "account_id": "69192f20-26e1-465c-829b-0069e4aa6649",
    "type": "credit",
    "amount": "30.00",
    "description": "Rent share",
    "reference_id": "tr-001",
    "created_at": "2026-10-27T20:35:19.524788Z"
  },
  "from_account_balance": "40.00",
  "to_account_balance": "30.00"
}
```

**Errors**

| Status | `code` | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Missing or invalid fields, `amount` ≤ 0, malformed UUIDs, or `from_account_id` equals `to_account_id` |
| 404 | `ACCOUNT_NOT_FOUND` | Either account does not exist (`details.account_id` says which) |
| 409 | `DUPLICATE_TRANSACTION` | `reference_id` already used on the source or destination account |
| 422 | `INSUFFICIENT_BALANCE` | The source account balance is less than `amount` |

`400` transfer to the same account:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request data",
    "details": [{
      "field": "body",
      "location": "body",
      "message": "Value error, from_account_id and to_account_id must be different accounts"
    }]
  }
}
```

## Example flow

The assignment's balance-consistency example, run end to end. Replace `$A` and `$B` with the
IDs returned by the first two calls.

```bash
# 1. Create two accounts (each starts at 0.00)
curl -X POST localhost:8000/accounts -H "Content-Type: application/json" -d '{"name": "Alice"}'
curl -X POST localhost:8000/accounts -H "Content-Type: application/json" -d '{"name": "Bob"}'

# 2. Credit 100, credit 50, debit 30, debit 20  ->  Alice's balance = 100.00
curl -X POST localhost:8000/accounts/$A/transactions -H "Content-Type: application/json" -d '{"type":"credit","amount":100,"reference_id":"c1"}'
curl -X POST localhost:8000/accounts/$A/transactions -H "Content-Type: application/json" -d '{"type":"credit","amount":50,"reference_id":"c2"}'
curl -X POST localhost:8000/accounts/$A/transactions -H "Content-Type: application/json" -d '{"type":"debit","amount":30,"reference_id":"d1"}'
curl -X POST localhost:8000/accounts/$A/transactions -H "Content-Type: application/json" -d '{"type":"debit","amount":20,"reference_id":"d2"}'

# 3. A debit larger than the balance is rejected (422); the balance stays 100.00
curl -X POST localhost:8000/accounts/$A/transactions -H "Content-Type: application/json" -d '{"type":"debit","amount":150,"reference_id":"d3"}'

# 4. Sending the same reference_id again is a duplicate (409); nothing changes
curl -X POST localhost:8000/accounts/$A/transactions -H "Content-Type: application/json" -d '{"type":"credit","amount":100,"reference_id":"c1"}'

# 5. Check the balance and the history (latest first, only debits)
curl localhost:8000/accounts/$A/balance
curl "localhost:8000/accounts/$A/transactions?type=debit&page=1&limit=10"

# 6. Transfer 30 from Alice to Bob  ->  Alice 70.00, Bob 30.00
curl -X POST localhost:8000/transfers -H "Content-Type: application/json" \
  -d "{\"from_account_id\":\"$A\",\"to_account_id\":\"$B\",\"amount\":30,\"reference_id\":\"tr-1\"}"
```
